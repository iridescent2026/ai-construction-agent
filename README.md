## 推荐体验

1. 登录页展开演示岗位账号，填入安全员并登录；每浏览器独立24小时模拟空间。
2. 设备监测搜索B-05，定位并返回，搜索保留。
3. 左侧设备影响链进入任务助手，查状态、候选影响和人员作业，核对来源、时间、版本及实际工具记录。无规则待核验，缺失或过期未知。
4. 生成草案并选维修账号，人工确认后才创建和指派工单。
5. 页首切换维修员，在维修闭环开始处理、提交原型凭证；另一复核员关闭或退回。关闭不自动解除区域告警。
6. GIS查看室外区域、动态观测与进入报警；影像不是实时视频，坐标未做现场配准。

原型演示账号：demo-safety / SafetyDemo!2026；demo-maintenance / RepairDemo!2026；demo-reviewer / ReviewDemo!2026；demo-observer / ObserveDemo!2026。正式项目勾选对应登录选项，私密管理员凭据禁止写入源码。

## 本地复现

Windows PowerShell：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_demo.py
```

打开 http://127.0.0.1:8080/ ，保留终端。默认8000、8001、8002、8080端口须空闲；冲突时先设置 `$env:DEMO_PORT_OFFSET='10000'`，网页改为18080。Linux/macOS使用 `.venv/bin/python`。首次依赖安装及卫星底图需联网；前端库和模型资产本地托管。

Docker：`docker build -t gongan-demo .` 然后 `docker run --rm -p 10000:10000 gongan-demo`。外部持久存储需DATABASE_URL；正式管理员密码通过FACTORY_ADMIN_PASSWORD私密配置，模型密钥可选。详见[云部署](docs/cloud-deployment.md)和[登录与巡视](docs/access-storage-inspection-v22.md)。

测试：安装requirements-dev.txt后运行 `python -m pytest -q`；前端运行 `node --test tests/*.test.cjs`。
