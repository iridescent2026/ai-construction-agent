# 真人原型对比实验操作说明

组织者邀请 3–5 位同学。比较范围为固定软件题的查表与辅助答题，设备、连接和 60℃条件都是原型配置；实验不测现场维修能力，也不能折算企业成本或安全收益。

## 准备账号和顺序

正式项目管理员通过页首“账号中心”创建每位参与者独立的只读账号，现场交付初始密码；参与者首次使用后自行改密。用正式项目登录，勿勾选创建个人模拟空间，勿使用 demo-* 账号，否则汇总排除其记录。参与者必须本人答题，组织者核对身份但报告只使用匿名编号。

将参与者编号设为 test01–test05。按编号奇偶分两组，每题交替第一种方法：test01、test03、test05 的第1/3题先人工，第2/4题先系统；test02、test04 反过来。记录实际顺序，不强行修改原始记录来符合分组。界面中的按账号推荐起始方法只是提示，实际采用组织者安排。

先用另一个练习账号熟悉按钮；不预看四道正式题答案。固定题为 fresh_alert、stale、no_trigger、missing，每人完成四题各两种方法，共8次。相同题的第二次可能产生学习效应，报告必须说明；小样本不进行夸大的显著性或推广结论。

## 参与者操作

1. 登录后从左侧设备影响链进入任务助手，展开“③ 人工查表 / 系统辅助 · 实际计时实验”。
2. 勾选本人完成声明，填写相关经验（例如“无设备维修经验，熟悉网页操作”）。
3. 按组织者给的顺序选题和方法，点击开始。人工组读取屏幕表格，自行填写观测判断、候选编号、位置未知人数和下一步；不使用其他 AI。
4. 系统组点击“运行实验助手”，核对实际工具结果，再自行填写四项答案。两组都由参与者本人点击提交。
5. 服务器记录开始和提交时间，显示得分。错误答题保留，不重做来替换第一次成绩。
6. 完成8次后导出本人实验 JSON，交给组织者。网络中断或放弃时保留未完成记录，另记原因；不要删除后重做并声称第一次成功。

## 组织者核对与报告

管理员或复核员读取 `/factory/operations/experiment-summary`；管理员账号中心可点击“导出参与者汇总”。导出仅统计声明本人完成、非演示、非备份恢复的账号。它不能替组织者核实身份或禁止作弊。个人报告包含本人的练习记录，汇总报告用于正式对比。

报告每种方法的尝试数、完成数、错误数、未完成数、全对率、四字段准确率和全部已完成记录的用时中位数。同一人同题同方法取第一次完成记录配对，分别报告全部配对和两种方法都全对的配对；同时保留负时间差。至少3人完成全部8次后才具备完整配对资料，仍不代表结果一定优于人工。

填写以下内容后才形成实际结果：

| 项目 | 实际填写 |
| --- | --- |
| 实验日期、版本、组织者 | 待采集 |
| 参与人数、匿名编号、经验 | 待采集 |
| 方法顺序、网络情况与中断原因 | 待采集 |
| 两组完成/尝试、错误、未完成 | 从原始汇总填写 |
| 全对率、字段准确率、中位用时 | 从原始汇总填写 |
| 全部配对及全对配对的时间差 | 从原始汇总填写 |
| 学习效应、样本小、固定软件题局限 | 必须说明 |

保留原始 JSON、组织者核对记录及异常说明。自动化测试、开发者录屏和演示账号不得计为真人实验成绩。
