# B-05 设备异常核查闭环（V19）

首页与 GIS 页的“工厂分析”内新增同一套任务助手。原 A/B、GIS、五项分析、纯建筑首页全景继续保留。

## 操作

1. 启动 python run_demo.py，进入首页或 workbench.html，从“工厂分析”导航进入设备异常处置。
2. 查询 B-05 状态、候选影响、人员与作业。默认没有工程适用规则，有效读数显示待核验；缺失或过期显示未知。
3. 在账号区点击“填入安全员演示账号”，然后登录。演示账号不会自动登录。
4. 如需验证软件异常分支，可勾选“使用流程测试条件”。60℃只是软件测试输入的分界，不是泵组工程限值；真实模式禁止此选项。
5. 点击“核查草案”，检查依据并选择维修账号，点击确认。草案不等于已经派单；确认成功才创建并指派一张工单。
6. 切换并登录维修账号，在“维修闭环”选择新工单、开始处理、填写凭证并提交。
7. 切换并登录复核账号，填写复核意见后关闭或退回。请求中手填 actor 不会改变服务器确认的账号身份。

观测示例仍在 GIS 的“数据接入与核验”：先登录安全员或维修账号，再填写或导入 JSON。手动导入会标为手动测试，并不证明真实设备接入。演示账号的数据、证据与结论不得作为真实现场记录。

## 演示账号

仅在 DEMO_MODE=1 且未配置自定义账号时启用：

|账号|密码|权限|
|---|---|---|
|demo-safety|SafetyDemo!2026|核查草案、确认派单、指派、计划与手动导入|
|demo-maintenance|RepairDemo!2026|被指派任务的开始、提交凭证、手动测试导入|
|demo-reviewer|ReviewDemo!2026|凭证复核、退回、连接依据复核|
|demo-observer|ObserveDemo!2026|查询，不能派单或修改工单|

演示密码公开供原型测试，不能证明真实人员身份。同一人切换两个演示账号并不构成真实岗位分离。验证的是服务器账号权限和不可用换姓名绕过的控制；正式应用需分发独立账号、核实人员与岗位。

密码以加盐 PBKDF2 保存；随机会话 token 在服务端只存哈希，一小时过期，退出撤销。相同账号十次失败后暂时阻止登录五分钟。前端会话在浏览器 sessionStorage，不保存密码。

## 同源工具与台账

一次任务读取一个工厂观测快照，查询连接、人员、计划与工单，记录实际工具输入、输出及版本。非路线的设备任务也可由 math 服务的 /chat 与 /chat_llm 转交 GIS 工作流；不会退回旧工地数据回答 B-05。

当前编排使用明确的任务规则，不声称运行了通用自主规划大模型：

观测与有效性 → 候选连接及依据 → 有效人员与未知位置 → 关联作业与工单 → 核查草案 → 安全员确认指派 → 被指派账号提交凭证 → 另一复核账号关闭或退回。

最小台账列明已知、设计假设、待核验。默认连接仍是候选关系；双向三跳查询不是故障传播计算。工厂无设备适用规则时，不以有效温度或压力推断正常。流量没有接入，不生成值。人员过期单列；没有计划或匹配记录不等于没有现场作业。

草案五分钟过期。确认时重新核对有效性、来源类别、规则分支、连接和计划，以及后台实例；变化返回 409，需重新生成。允许同一状态下观测正常更新，留存草案时与确认时两套依据，而不是把更新后的值冒充已审阅的值。创建、指派、消费草案在同一 SQLite 事务，重复确认返回原工单；写入失败不消费草案或留下半张工单。

## 接口

|方法与路径|用途|
|---|---|
|GET /factory/workflow/case/{id}|同源核查证据；useTestRule 默认 false|
|POST /factory/workflow/chat|query、entityId、useTestRule；真实工具结果，不直接控制设备|
|POST /factory/workflow/drafts|登录安全员生成草案|
|POST /factory/workflow/drafts/{id}/confirm|草案所有者确认，assignee 为有效维修账号 ID|
|POST /factory/auth/login|username、password，返回会话|
|GET /factory/auth/me、/users|当前账号、可用岗位账号|
|POST /factory/auth/logout|撤销当前会话|

认证写入使用 Authorization: Bearer token。旧工单、计划、连接、电表、照片获取及手动观测接口也执行相应账号检查，不能绕过新入口。工单 actor 取登录账号；处理需与指派一致，复核需对应岗位且不能是处理账号。

导入保留 measurementProvenance / positionProvenance：手动测试、采集账号声明、旧来源未核验或模拟。collector 账号证明导入账号，不证明设备真实性；尚无硬件设备证书或协议适配器。

## 真实配置与范围

本阶段仅面向本机单项目、单进程原型；没有项目隔离、企业统一身份、硬件认证或工程规则维护平台。

DEMO_MODE=0 会禁用默认演示账号、演示规则，并清除对应演示会话。由部署者通过 FACTORY_ACCOUNTS_JSON 配置独立的 id、name、role、password；密码至少12位，支持 safety、maintenance、reviewer、observer、collector、admin。配置变更撤销受影响账号会话。

账号库与工厂数据库同目录，后缀 .accounts.db，不随源码包发布。不要提交真实账号配置或数据库。

旧演示工单仍保留历史姓名；若原指派是“演示维修员”，安全员需要重新指派到有效维修账号再处理，不伪造旧记录为已认证历史。
