# 电气风险模块

负责人：lry

## 文件说明

| 文件 | 作用 |
|------|------|
| `main.py` | FastAPI 服务：模拟设备数据 + 风险评分模型 + 5 个接口 |

## 已实现接口

| 接口 | 方法 | 功能 |
|------|------|------|
| `/devices` | GET | 查询所有电气设备状态与风险 |
| `/devices/{device_id}` | GET | 查询单个设备详情 |
| `/devices/batch` | POST | 批量查询（传 device_ids 列表） |
| `/devices/{device_id}/history` | GET | 查询设备风险历史（保留最近 20 条） |
| `/devices.geojson` | GET | 导出 GeoJSON，供前端地图渲染配电箱图层 |

详见 `../docs/api.md`

## 风险评分模型

把负荷、温度、漏电三项指标各自映射到 0-1 的**超标程度**，再加权融合：

```
risk_score = 0.45 × 漏电超标度 + 0.35 × 负荷超标度 + 0.20 × 温度超标度
```

每项指标采用「**安全阈值 → 危险阈值**」线性映射：低于安全阈值记 0 分（正常工作
状态不产生风险），高于危险阈值记 1 分，中间线性插值。

| 指标 | 安全阈值 | 危险阈值 | 说明 |
|------|---------|---------|------|
| 负荷 load | 60% | 95% | 低于 60% 属轻载，接近满载记满分 |
| 温度 temperature | 40℃ | 70℃ | 常温以上开始累计风险 |
| 漏电 leakage | 0.1mA | 0.5mA | 超 0.1mA 即需关注 |

### 权重设定依据

| 指标 | 权重 | 理由 |
|------|------|------|
| 漏电 | 0.45 | 直接导致触电伤亡，是临时用电最致命的风险 |
| 负荷 | 0.35 | 过载会引发电缆发热甚至起火 |
| 温度 | 0.20 | 温度多为过载/漏电的**结果性指标**，非独立成因，权重最低 |

### 风险等级与预警

- 等级划分：`≥0.7 高` / `≥0.3 中` / `<0.3 低`
- 预警触发阈值与评分阈值**分开设置**（负荷 ≥80%、温度 ≥55℃、漏电 ≥0.3mA），
  避免边界值被频繁记为异常
- 预警文字带严重度前缀：`严重：过载、高温、漏电`

### 设计取舍说明（答辩要点）

早期版本采用「物理量 ÷ 满量程」的纯比例累加，存在一个问题：
负荷 60% 属正常工作状态，却会与负荷 0% 一样被计入风险，导致低风险设备
也被判定出较高分数。现版本引入安全阈值后，正常运行的设备稳定停留在低风险区，
只在指标真正逼近危险线时才快速抬升评分，更贴合现场临时用电的实际评判逻辑。

## 动态数据模拟

每次请求会对设备指标做小幅随机抖动（负荷 ±10%、温度 ±5℃、漏电 ±0.1mA），
模拟现场传感器实时上报的效果，使演示时评分与预警会实时变化。

## 运行

```bash
python -m uvicorn main:app --port 8001
```

访问 `http://127.0.0.1:8001/docs` 查看接口文档并在线测试。

注意端口用 **8001**，与 GIS 模块的 8000 端口区分（前端 `app.js` 中
`ELECTRICAL_API` 即指向 8001）。
